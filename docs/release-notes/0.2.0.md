**libreOMR 0.2.0** adds multi-part scores, lyrics from PDF text and bundled offline
OCR, independent voice editing, and slurs, ties and dynamic wedges across systems.

libreOMR remains an **early prototype** for local optical music recognition.
Recognition results require musical review and correction.

## Changes since 0.1.2

- **Multi-part scores:** Bracketed systems can be grouped into persistent parts
  across systems and pages. Positioned PDF labels can supply part names, which
  remain editable. Header recognition supports 4/2 and octave-down treble clefs;
  key and meter inheritance follow each part. MusicXML exports separate named
  parts with continuing measure numbers and octave-displaced clefs.
- **Lyrics and offline OCR:** Positioned PDF text and bundled RustO/RTen models
  propose lyric syllables without an external OCR service or runtime model
  download. Multiple verses, printed verse labels, word position, extenders and
  placement above or below the staff are preserved in projects and MusicXML.
  Compact verse editors support correction, review, navigation and undo/redo.
  Heuristics exclude common performance directions, footers and detached stanza
  blocks from note associations while retaining the original source text.
- **Shared score preview:** All systems on the current page share one canvas,
  aligning notes and barlines across parts and displaying their lyric verses.
  Fit mode follows the available width; scrolling and zoom support inspection
  of larger scores. Selecting an object brings its preview into view, and
  clicking a lyric syllable selects its note.
- **Voices and multiple selection:** Notes and rests support manually assigned
  voices 1-4 within a staff. Measure checks and MusicXML keep voice durations
  separate, and the preview uses opposing stems. Ctrl/Cmd-click, Shift-click and
  Ctrl/Cmd+A support selecting several objects for shared duration or voice
  edits and deletion, with one undo step per shared edit.
- **Bows and dynamic wedges:** Slurs, ties, crescendos and decrescendos can attach
  to selected notes and continue across system breaks on the same page. Scan
  and preview display separate fragments while MusicXML retains matching
  start/end pairs. Attached endpoints follow note corrections; bow direction
  and endpoints can be edited. Tie handling preserves compatible accidentals
  across barlines and systems.
- **Time-change recognition:** Cached templates, geometry checks and bounded
  comparisons reduce the work needed to find inline meter changes while
  preserving the existing acceptance rules. Regression tests compare results
  with the exhaustive search. See the included time-change performance notes
  for measurements of this recognition stage.
- **Packaging and checks:** OCR models and dependency notices ship with the
  application. Pinned supplemental FlatBuffers and RTen license texts include
  upstream sources and checksums. CI checks the complete dependency graph's
  license texts before packaging, alongside cross-platform Rust tests,
  formatting, Clippy and Python packaging tests.

## Existing projects and limitations

Existing version 1 and 2 projects remain readable. Optional fields preserve
parts, lyrics, voice assignments and note anchors; older projects without voice
assignments use voice 1. Reimport or recognize the source again to obtain new
recognition proposals. Save existing corrections first: recognizing again
replaces the active page's proposals and corrections.

Automatic recognition does not reconstruct independent rhythmic voices within
one staff. Complex orchestral grouping, single-line percussion, pickup inference,
lyric alignment and cross-system lyric extenders still require further work or
manual correction. OCR spellings and note-to-syllable associations are proposals.
Cross-system bow and wedge connections are currently limited to one page.

## Downloads and startup

Extract the entire archive for your platform:

| Platform | Archive | Application |
| --- | --- | --- |
| Windows x86_64 | `libreomr-0.2.0-x86_64-pc-windows-msvc.zip` | `libreomr.exe` |
| Windows ARM64 | `libreomr-0.2.0-aarch64-pc-windows-msvc.zip` | `libreomr.exe` |
| Linux x86_64 | `libreomr-0.2.0-x86_64-unknown-linux-gnu.tar.gz` | `libreomr` |
| macOS Apple Silicon | `libreomr-0.2.0-aarch64-apple-darwin.zip` | `libreOMR.app` |

Each binary package also includes `omr-benchmark`, the user guide, documentation,
public sample score and license notices. OCR models and language catalogs are
embedded in the application. `SHA256SUMS` lists checksums for all five release
archives, including the corresponding source archive.

Linux requires a graphical X11 or Wayland session, system libraries for XKB,
Wayland and EGL, and `xdg-desktop-portal` with a matching desktop backend. Place
the extracted directory in a permanent location and run `python3 install-desktop.py`
inside it to install the application-menu entry for the current user.

On macOS, copy `libreOMR.app` to Applications. The app is not signed or notarized;
first launch may require approval in **System Settings > Privacy & Security**.
Intel Macs are not supported. Windows requires Windows 10/11 and working
Direct3D 12 support; the README describes the Vulkan alternative.

## Source code and license

libreOMR uses **GPL-3.0-or-later**. The
`libreomr-0.2.0-source.tar.gz` archive includes corresponding source code and the
Cargo dependencies pinned by `Cargo.lock`. With Rust **1.94** or newer, native
build tools and system libraries installed, build it offline with:

```sh
cargo build --release --locked --offline
```

Fonts, OCR models, dependencies and the sample score retain their own notices.
See the included README and `docs/polyphonic-scores-and-lyrics.md` for usage
details and current recognition limitations.
