**libreOMR 0.1.1** verbessert den Windows-Start, die Fehleranzeige und die
Einbindung der Anwendungssymbole auf Windows, macOS und Linux.

libreOMR bleibt ein **früher Prototyp** zur lokalen optischen Notenerkennung.
Erkennungsergebnisse müssen musikalisch geprüft und korrigiert werden.

## Änderungen gegenüber 0.1.0

- **Windows-Grafik:** Der Build enthält den wgpu-Renderer und verwendet
  standardmäßig Direct3D 12. Damit entfällt die bisherige OpenGL-Abhängigkeit
  beim Start. Benötigt werden Windows 10/11 mit funktionierender
  Direct3D-12-Unterstützung. Die README beschreibt einen alternativen Start
  über Vulkan bei vorhandenem Vulkan-Treiber.
- **Sichtbare Fehler:** Startfehler und Rust-Panics werden in einem nativen
  Fehlerdialog angezeigt, auch wenn das Hauptfenster noch nicht geöffnet
  werden konnte. Der Dialog enthält technische Details und den Pfad zum
  Fehlerbericht. Unter Windows liegt dieser normalerweise unter
  `%LOCALAPPDATA%\libreOMR\error.log`, ersatzweise unter
  `%TEMP%\libreOMR\error.log`. Bei Rust-Panics enthält der Bericht einen Stacktrace.
- **Windows-Icon:** Die EXE enthält das Anwendungssymbol in sieben Größen für
  Explorer und Verknüpfungen, einschließlich hoher Bildschirmauflösungen.
- **macOS-Icon:** Finder- und Dock-Symbole verwenden gemeinsame vorbereitete
  Bildgrößen einschließlich Retina-Auflösungen bis 1024 Pixel. Beim Paketieren
  werden der Icon-Verweis und die ICNS-Datei geprüft.
- **Linux-Integration:** Ein Desktop-Eintrag, Icons für das Anwendungsmenü und
  eine passende Anwendungs-ID für die Fensterzuordnung werden mitgeliefert.
  `python3 install-desktop.py` richtet den Menüeintrag ohne Administratorrechte
  für den aktuellen Benutzer ein.
- **Paketierung und Prüfungen:** Ausführungsrechte für Linux- und macOS-Binärdateien
  werden in den Archiven gesichert. Zusätzliche Prüfungen kontrollieren
  Icon-Dateien, den Linux-Desktop-Eintrag und unter Windows den sichtbaren
  Fehlerdialog bei fehlender Grafikunterstützung.

## Downloads und Start

Das passende Archiv vollständig entpacken:

| Plattform | Archiv | Anwendung |
| --- | --- | --- |
| Windows x86_64 | `libreomr-0.1.1-x86_64-pc-windows-msvc.zip` | `libreomr.exe` |
| Windows ARM64 | `libreomr-0.1.1-aarch64-pc-windows-msvc.zip` | `libreomr.exe` |
| Linux x86_64 | `libreomr-0.1.1-x86_64-unknown-linux-gnu.tar.gz` | `libreomr` |
| macOS Apple Silicon | `libreomr-0.1.1-aarch64-apple-darwin.zip` | `libreOMR.app` |

Jedes Binärpaket enthält außerdem das Benchmark-Programm `omr-benchmark`,
die Nutzungsanleitung, die öffentliche Beispielpartitur und Lizenzhinweise.
`SHA256SUMS` enthält die SHA-256-Prüfsummen der Release-Archive.

Unter Linux werden eine grafische X11- oder Wayland-Sitzung und die
Systembibliotheken für XKB, Wayland und EGL benötigt. Der Dateidialog verwendet
`xdg-desktop-portal` mit einem passenden Desktop-Backend. Die Pakete werden auf
Ubuntu 22.04 gebaut und bündeln diese Systembibliotheken nicht.

Für den Linux-Menüeintrag den entpackten Ordner zunächst an einem dauerhaften
Ort ablegen und darin `python3 install-desktop.py` ausführen (Python 3 erforderlich).
Der Menüeintrag startet das Programm aus diesem Ordner. Nach einem Verschieben
den Befehl erneut ausführen.

Unter macOS `libreOMR.app` in den Programme-Ordner kopieren. Die App ist nicht
signiert oder notarisiert; beim ersten Start kann eine Freigabe unter
**Systemeinstellungen > Datenschutz & Sicherheit** erforderlich sein.
Intel-Macs werden nicht unterstützt.

## Quellcode und Lizenz

libreOMR steht unter **GPL-3.0-or-later**. Das zusätzliche Archiv
`libreomr-0.1.1-source.tar.gz` enthält den zugehörigen Quellcode und die durch
`Cargo.lock` fixierten Cargo-Abhängigkeiten. Mit Rust ab Version 1.92 und den
nativen Build-Werkzeugen und Systembibliotheken lässt es sich offline bauen:

```sh
cargo build --release --locked --offline
```

Weitere Hinweise zu Installation und Bedienung stehen in der mitgelieferten
README. Fonts und Beispielpartitur behalten ihre eigenen Lizenz- bzw.
Gemeinfreiheitsangaben.
